# 재회 레인 v2 — Creative Director 전달 문서 보관소

브랜치: `jiknyeo-reunion` · 상품: **견우의 재회예보**(`reunion-saju`) · 개설 2026-09-05

GPT(ChatGPT 웹)가 기획하고, 검증·구현은 이쪽에서 한다. 직녀 v2(`creative/jiknyeo-v2/`)와 같은 방식이되
**대화는 따로 연다** — 한 대화에 두 상품을 섞으면 컨텍스트가 오염된다.

## 이 폴더의 파일

| 파일 | 무엇 |
|---|---|
| `A_임무서.md` | GPT에게 주는 역할·규칙·출력 규격 |
| `B_현행재고표.md` | 지금 화면에 실제로 뜨는 것 전부(코드 실측). **기획 문서보다 우선** |
| `_GPT업로드용_재회레인팩.md` | A~E를 이어 붙인 **업로드 본체**(187KB · 20절) |
| `_GPT_첫메시지.md` | 새 대화에 붙여넣을 첫 지시문 |

업로드 꾸러미(파일 2 + 이미지 8)는 바탕화면 **`재회레인팩_2026-09-05`** 폴더에 모여 있다.
경쟁사 실물 이미지는 저장소에 넣지 않는다(아카이브는 저장소 밖에 둔다는 기존 규칙).

## GPT가 돌려줄 문서 (여기에 저장한다)

| 문서 | 파일명 관례 |
|---|---|
| Storyboard | `storyboard_<날짜>.md` |
| Visual Bible | `visual-bible_<날짜>.md` |
| Asset List | `asset-list_<날짜>.md` |
| Implementation Spec | `implementation-spec_<날짜>.md` |

받은 뒤 순서: **저장 → 코드·문서와 대조해 정정 목록 → 형님 컨펌 → 구현.**
검증 없이 기획서를 그대로 코딩하지 않는다(직녀 v2에서 GPT가 말한 「PAGE 01~29 사양」이 저장소에 없었다).
