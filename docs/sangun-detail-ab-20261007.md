# 박수무당 이전 상세 / 새 상세 테스트

형님 지시: “그럼 테스트를 해보자” (2026-10-07).

## 고정 조건

- `sangun_detail_old_new_v1`: 이전 상세(old) 50%, 새 상세(new) 50%.
- 입력을 마치고 상세에 도착할 때 별도의 무작위 배정. 서명한 90일 쿠키로 재방문·로그인 왕복에도 같은 안 유지.
- 게이트 A/B와 독립 배정. 광고 소재·게이트 동작·가격·결제 UI는 이 배포에서 변경하지 않음.
- 두 안 모두 현재 상품 DB 가격 사용. 단품 24,900원 / 회원 23,000원, 2종 31,900원 / 회원 30,000원. 2종 기본선택 및 고객의 이후 선택 유지.
- old는 현재 코드에 보존된 TeaserStep, new는 SangunPersonalDetail. 과거 전체 배포를 되돌리는 방식이 아니므로 공통 결제 오류 수정도 유지.

## 측정

- 단위: 서명한 detail_subject(브라우저별 익명 ID). 세션 수와 섞지 않음. 쿠키 삭제·다른 기기는 연결 불가.
- `detail_entry`: 상세 데이터 도착 및 기존 로딩 종료 직후. 새 화면의 추가 로딩·실패도 처음 배정된 안에 포함.
- `detail_exposure`: 실제 렌더 완료. rendered, fallback으로 새 상세 대신 이전 화면이 나온 경우를 구분.
- 비교: 상세 도착 후 **24시간 이내 실제 결제자 / 상세 도착자**. 24시간이 지난 방문자를 주 집계로 사용. 미성숙 방문자는 잠정치로 표시. 7일 지연 구매는 별도 보조 집계.
- 보조: 결제 옵션 노출, 결제창 진입, 실제 렌더 완료, 대체 화면 비율, 방문자당 환불 차감 매출.
- 구매는 브라우저 purchase 이벤트가 아닌 orders의 paid_at/status/amount와 서버 detail_order_link로 검증. purchase_tracking.context에도 서명한 배정을 보관해 서버 연결 이벤트 누락 시 보완.
- 결제 전 기존 주문을 재사용하는 경로도 연결. 단품·2종·3종 포함, 타 상품의 별도 구매 제외.
- 최초 상세 도착 때 게이트/소재를 고정해 각각 나누어 비교. QA/preview/데모, 테스트 주문, 배정·주문 연결 충돌 제외 및 수량 표시.
- 최소 7일은 수집하고, 표본과 불확실성을 확인한 뒤 판단. 기간이 찼다고 자동으로 승자를 정하거나 바꾸지 않음. 초기 수 건으로 중단하지 않음.

## 검수와 중단

- `?demo=1&detail_qa=old` / `?demo=1&detail_qa=new`: 기존/새 상세 강제 검수. 화면에 검수·통계 제외 표시. QA 쿠키는 이후 방문과 주문에도 유지. 고객에게 이 링크를 배포하지 않음.
- 서명값·QA 여부는 서버 검증. 클라이언트가 실험 라벨이나 주문 연결을 위조할 수 없음.
- 배정 API 실패 시 현재 새 상세를 보여주고 `detail_assignment_unavailable` 기록. 정상 배정 분모에 섞지 않음.
- 새 상세 로드/렌더 실패 또는 8초 내 준비 실패 시 이전 상세로 복구. 원래 new 배정 분모는 유지.
- 긴급 중단: `SANGUN_DETAIL_AB_ENABLED=0` 후 재배포하면 현재 새 상세 단일 운영으로 복귀. 가격/광고/게이트는 별도 설정.
- 읽기 전용 집계: `scripts/report-detail-ab.sql`. 첫 CTE의 conversion_window를 7 days로 바꾸면 지연 구매 보조 집계.

운영 시작 시각과 검수 결과는 배포 완료 후 작업 기록에 추가한다.
